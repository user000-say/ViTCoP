## 2. What E014 implements

Input: CLIP 576 patch embeddings and ViTCoP raw CLS attention.
Frozen original Core = highest-attention 172 patches.

Exchange:
- choose `b` discarded candidates from the 404 residual patches,
- evict `b` original Core patches,
- pass exactly `172` **eligible** patches to Llama (sorted by source patch ID),
- unchanged QED selector and SDPA forward path; unchanged E012 S=D deletion.

Residual candidate gain (E013-notes COVER *proxy*):
`G_i = a_i * (1 - max(0, cos(x_i, mean(x_all))))`.

Eviction risk:
`R_j = a_j * (1 - max(0, max_{k in Core, k != j} cos(x_j, x_k)))`.

Budget proxy:
`U(b) = sum(top_b G) - lambda * sum(bottom_b R)
        - penalty * b * mean(a)`,
for b in `{0,8,16,24,32}`. `b*=argmax(U(b))`.

**Important scientific limitation:** gain and risk are not automatically
calibrated as comparable utilities. Lambda/penalty are a registered
hyperparameter hypothesis, NOT a proven oracle. Their trade-off must be
measured and fixed before full held-out test evaluation. An `AEE` method
that always chooses 0 or 32 is not empirically adaptive.

**Important engineering limitation:** The original `e013_stage1_support.py`
was **not** among the two newly uploaded source files. It is required by the
legacy E013 code, and is intentionally required by `E014_VARIANT=FIXED_COVER`
to compare against the *exact* pre-existing E013 COVER. The `AEE`,
`FIXED_RISK`, `BASE`, `ADAPTIVE_B_ONLY`, and `FIXED_COVER_PROXY` methods
do **not** import the absent file. Do not label `FIXED_COVER_PROXY` as
exact E013 COVER until selected-token identity has been confirmed.

## 5. Run an existing evaluator or smoke entrypoint

Pass **your own existing project command** to one of the wrappers:

```bash
# Audit/smoke; do not use these settings for TTFT latency.
E014_VARIANT=AEE E014_AUDIT=True E012_KV_AUDIT=True \
  scripts/run_e014_k96.sh python YOUR_EXISTING_SMOKE_SCRIPT.py [args...]

# Canonical latency: audits explicitly disabled.
E014_VARIANT=AEE E014_AUDIT=False E012_KV_AUDIT=False \
  scripts/run_e014_k96.sh python YOUR_EXISTING_LATENCY_SCRIPT.py [args...]

# Exact historical COVER control; original e013_stage1_support.py required.
E014_VARIANT=FIXED_COVER E014_B=16 \
  scripts/run_e014_k96.sh python YOUR_EXISTING_EVAL_SCRIPT.py [args...]
```

`E014_LAYER` is 8 by default; layer 12 is allowed for a bridge experiment.
The wrappers set all known critical frozen env vars, e.g. USE_VITCOP=True,
E007 ORIGINAL_172, E006/QED, E010, E012(S=D), STAGE3_POLICY=skip.
They do **not** guess missing model paths, dataset paths or evaluator flags.

**K64/K32:** E014 contains **E014-scoped** relaxations for earlier E012/E007/E006
K96 guards. This permits configuration, but is NOT evidence of runtime or
quality correctness at K64/K32. K96 smoke is prerequisite; verify KV topology,
decode1/decode2, visual length, selector calls at each new K.

## 6. Four full benchmark scheduling

Create `commands.json` with four *existing and VERIFIED* full-evaluation
commands. Each string may use placeholders `{out_dir}`, `{k}`, `{benchmark}`,
`{gpu}`, `{method}`, `{b}`, `{layer}`, `{seed}`.

```json
{
  "GQA": "python YOUR_GQA_EVAL.py --output {out_dir}",
  "POPE": "python YOUR_POPE_EVAL.py --output {out_dir}",
  "MME": "python YOUR_MME_EVAL.py --output {out_dir}",
  "MMBench": "python YOUR_MMBENCH_EVAL.py --output {out_dir}"
}
```

**These are placeholders, not verified executable commands.**
Adapt from your frozen E013 evaluator launch commands. For each run,
the actual evaluator/postprocessor must write:
`{out_dir}/eval_summary.json` with at least `{"n": <full_N>, "score": <metric>}`.
Choose the exact benchmark's standard metric, e.g. POPE F1. In historical E013,
full-N counts were GQA 12578 / POPE 9000 / MME 2374 / MMBench 4329;
these are supplied in `configs/expected_n_e013_protocol.json`.
Verify that the current evaluator uses the SAME splits/filtering before reuse.

```bash
python scripts/run_e014_suite.py --dry-run --plan k96
python scripts/run_e014_suite.py \
  --plan k96 --gpus 0,1,2,3,4,5,6,7 \
  --cwd /YOUR/VITCOP_REPO \
  --commands-json /path/commands.json \
  --expected-n-json /path/expected_n.json \
  --out logs/e014/full_k96

# When K96 identity/accuracy/KV pass:
python scripts/run_e014_suite.py \
  --plan k64 --cwd /YOUR/VITCOP_REPO \
  --commands-json /path/commands.json \
  --expected-n-json /path/expected_n.json \
  --out logs/e014/full_k64
```

Full checks are **strict by default**: absent/mismatched `n` fails the job.
`--allow-unverified` and `--allow-subset` are smoke only.
The scheduler distributes jobs over 8 GPUs and records JSONL manifest/logs.
It **does not** invent evaluation implementations or N, and cannot itself
confirm evaluator correctness beyond the summary file.

For offline Stage1 audits:
```bash
python scripts/analyze_e014.py --audit-log path/to/smoke.log
```
For 4-full-N completed comparisons:
```bash
python scripts/analyze_e014.py --manifest logs/e014/full_k96/manifest.jsonl
```
