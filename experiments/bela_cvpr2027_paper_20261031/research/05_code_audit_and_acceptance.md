# 源码核查、机制证据与交付验收

## 1. 先恢复生产事实，再完善方法

事实优先级：与报告结果对应的生产代码提交及运行配置 → 原始预测/结果文件 → 作者汇报 → 历史参考实现 → 既有论文草稿。不同层级有冲突时记录具体差异，不能从漂亮的草稿反推算法。

读取已有源码、日志和配置，无需先加载模型。记录 `git rev-parse HEAD`、工作区未提交修改和实际配置路径，避免把历史候选写成当前算法。保持生产代码不变；本轮只修改论文和作者记录。

历史记录提供的定位线索：

```bash
rg -n 'e013_choose|FIXED_COVER|select_question_anchored|dual_metric|visual_metric|RDRIFT|rdrift|LAST_ENTRY_METRIC' 实际源码目录
```

可能相关的历史路径为 `experiments/elva_r3/llava_stage1.py`、`LLaVA/llava/model/e018_stage2_support.py`、`query_anchor.py`、`llava_adapter.py`。这些只是索引线索，本包不声称它们已在生产仓库定位。源文件可能已改名，应沿实际调用关系追踪。

每个关键定义交付：真实文件/函数/行号、输入输出张量、数学操作、调用配置、与报告结果的对应。结果写入 `research/open_questions.md` 或同一份 `research/source_audit.md`，不另造大量状态报告。

### QA 参考代码的具体检查点

- 外部 raw 分数与 embedding 代理互斥；二者不能混写为同时使用。
- embedding 路径为投影视觉表示与问题 embedding 均值余弦，不自动等于经过专门训练的图文语义对齐器。
- `std(unbiased=False)` 为总体标准差；`torch.median` 对偶数长度的约定需保留。
- 原始分数 std 小于 0.008 会保持原生集合；这项阈值是设计条件，不是可靠性已经校准的证明。
- G 为各视图归一化余弦截断后平均；适配器只传一个融合张量时，M=1，不能写成仍分别处理两个视图。
- 默认候选池 16/12、B8、γ0.08、ν阈值0.05、ε0.005、λ0.5、saliency_guard_slots=0。
- 每次按当前集合重算候选；先前移除者可再次成为候选。操作不是强制换入 8 个此前从未出现的 ID。
- 取最大有限可行 J，没有单独的 J>0 检查；没有全局最优或调用一次即稳定的保证。

不具备 C1/C2/C4 的完整定义时，可以先完成背景、证据整理和不依赖该定义的正文；但 Method 仍属存在明确缺口的工作稿，不能声称已经满足完整复现。

## 3. 有效性消融与机制证据分别服务什么问题

先查作者已完成的结果。下表是证据用途，不是本轮新增 GPU 任务清单。缺少的项目仅记录；不得填预期分数。

| 要支持的解释 | 最小有区分力的比较/分析 | 需控制什么 | 不足以支持它的结果 |
| --- | --- | --- | --- |
| 双深度改变了候选关系 | 已有单深度/双深度成对结果，加近邻分歧与所选身份分析 | 后续 Native、QA、日程一致 | 换层同时换日程的总增益 |
| Native 基础有独立价值 | 原生/替代初始化的已有同预算对照 | q、G、QA 步数和执行预算可比 | 四个组件一起移除后的退化 |
| 问题身份参与收益 | 真实问题、错配、匹配随机 | 换入数量、预算、评测协议；报告未完成任务 | QA 优于仅原生 |
| 覆盖约束约束了有害替换 | 去门控对照；同时记录 D、A、ΔC 与任务结果 | q、novelty、候选池与预算固定；实际交换数另报 | 只展示被接受交换的 ΔC 下界 |
| 有限适配比一次联合选择更合适 | 同信息、同 K/日程下的已有联合选择与 QA 比较 | q/G 空间、调参协议、实际成本；不可要求两者循环次数相同 | 与不同论文公开表直接比精度 |
| B8 的适用性 | 已有交换数/收益/覆盖变化/耗时曲线 | 依据独立验证选择设置，报告全范围 | 用默认值或“两个阶段”解释最优 |
| 早期参与具有独立作用 | 固定 token 身份比较入口即删与参与到剪点再删，核查 KV 路径 | 删除其余身份、日程与 cache 因素；不完全可比时明确 | 最终大多被删但总性能提高 |

真实问题优于错配证明依赖问题身份，不等于对问题噪声具有鲁棒性。覆盖门控的代理界可以直接由代码推导，但其下游意义需要对照。若已有四模块消融全部正向，仍不能自动推导四者有协同效应；交互效应需要相应因子比较。

## 4. 最近邻核查后的改写规则

以下结论已不宜作为我们的首次发现：问题相关性重要；保留集合应减少重复；视觉和文本覆盖可以联合；删除效果依赖层位/集合；入口覆盖后继续渐进精炼。相关先例见 `06_closest_work.md`。

保留值得写的具体问题：问题代理改变候选身份时，会如何改变已有视觉代表关系；实际算子如何通过有限交换与覆盖变化约束它；在固定日程下观察到什么效果。若新材料削弱某个机制解释，调整对应主张，不把算法和实验一起推倒重做。

## 5. 审稿与修订的执行标准

Reviewer 先读论文与来源，诊断后交 writer 修改。当前稿的实验正文按请求未写，不能把“缺实验章节”伪装成未知缺陷；可以判断现有主张需要什么证据，但不模拟完整投稿已评完。

评审集中回答：

1. 一句话能否说清研究问题和具体操作差异？
2. 与 MMTok、MoB、CDPruner 及 2026 最近邻相比，贡献是否仍成立？
3. Native、QA、RDRIFT 的每个符号能否在真实代码中找到？
4. 摘要/引言的强主张是否超过作者结果与已核对分析？
5. 每个段落是否解释了一个必要关系，而非重复模块优点？

每项问题给原句、位置、依据、修改目标，按影响排序。不报虚构录用概率、独立审稿人数或保证中稿结论。Writer 修复后只复核变化及未解决问题。

## 6. 数字与来源完整性

- 核查 raw metric、百分比、百分点、MME 总分和归一化均值；保持显示精度一致。
- `W=1024`、平均32、末层10和入口64分别写清。
- 同 W 不自动同 FLOPs、同延迟、同 cache。实际成本须覆盖完整视觉塔、projector、selector、数据搬运/同步、prefill 和 decode。
- 查每条引文支持所在句子；别把原论文较早版本的描述或“作者声称”扩大为领域事实。
- 无法从原始出处证实的条目或比较，先核查再保留，不用模型记忆补 metadata。
- 构造示例、算法性质、作者报告的实验、文献结果和本轮实际执行事项明确分开。

## 7. 模板与 PDF 验收

保留原模板关键文件哈希，校验入口的 `10pt,twocolumn,letterpaper`、review 选项和匿名作者。中文稿采用现有 XeLaTeX/BibTeX 构建；中文支持不修改模板版心。不得通过私调字号、边距、行距或负间距隐藏超页。

实际运行编译，检查未定义引用/编号、缺字、溢出、字体嵌入、Letter 尺寸和页数。渲染最终 PDF 逐页看双栏顺序、公式断行、算法、图中文字、参考文献和 LLM Usage Statement。编译通过不等于视觉检查通过。

已附的底稿 PDF 是此前编译结果。任何正文变化后必须重编译；不能只复制旧 PDF 更名。若本机缺引擎或网络限制导致无法修复，明确报告实际阻塞与已完成部分，继续完成可执行工作，不伪造编译成功。

## 8. 最终回报格式

向作者交付完整源码和实际 PDF；简要解释中心主张如何成立、修改了什么、实际核查了什么。只将会影响复现或结论的未解决问题单列。保持作者记录独立，正文不出现待办、审核等级或内部阶段标签。
