# 正文蓝图：让每一段推进同一个研究问题

写作顺序建议为 Method → Related Work → Introduction → Conclusion → Abstract，正文阅读顺序保持标准论文顺序。以下组织是对 BELA 的建议，不宣称 15 篇范文具有相同段数。

## 摘要：先让读者理解为什么需要剪，再讲如何剪

承担五项任务：建立长视觉序列的推理成本；指出严格预算中的具体选择取舍；给整体方法；解释最关键操作；用一个完整、口径清楚的结果收束。学习 VisionZip、ViTCoP 的必要性铺垫，以及 MMTok 用统一决策对象组织摘要的方法。

不要以四个模块缩写开头，不要把 94.44% 数量预算减少写成延迟加速，也不要在未完成验证时加入跨架构、视频或 SOTA 断言。

可供 writer 修改的中文候选正文：

> 大量视觉 token 增加了视觉语言模型的推理计算与缓存开销，压缩冗余视觉序列因而成为提升推理效率的重要途径。然而，在严格预算下，增强当前问题的相关性也可能移除难以替代的视觉代表。本文提出 BELA，一种基于覆盖约束条件更新的免训练视觉 token 剪枝框架。BELA 从视觉代表集合出发，利用问题相关性和视觉新颖性提出少量同容量交换，并通过覆盖变化约束控制更新对原始视觉内容的影响；所选候选随后在 Decoder 中逐步精炼。该过程将任务适配落实为有限的集合重配置，使加入收益与移除损失共同决定候选更新。在 LLaVA-1.5-7B 的六项评测中，BELA 采用层平均 32 个视觉 token 的配置，将视觉 token-layer 预算减少 94.44%，保留完整模型 95.34% 的平均归一化性能。

这段不替代生产代码核查；特别是“视觉代表集合”的实际构造需写入 Method。完成其余章节后再调整摘要，保证每项表述都有正文落点。

## Introduction：从领域必要性走到我们的特定问题

建议 6–7 个连贯段落，按信息密度合并或拆分。

| 段落职责 | 读者应获得什么 | 依据与写法 |
| --- | --- | --- |
| 1. 能力与发展 | VLM 为什么重要，更多视觉细节为何有用 | 选少量基础与当前架构出处；模型清单服务背景 |
| 2. 成本与冗余 | 长视觉前缀为何值得压缩 | 576 等具体例子、注意力 O(n²d) 项、预填充与 cache；用相关工作支撑可压缩性 |
| 3. 已有方法 | 该领域已解决哪些选择问题 | 视觉侧压缩、集合去重、条件选择和渐进处理；不抹去已有贡献 |
| 4. 最近邻之后的问题 | 我们研究的额外决策是什么 | 正面承认 CDPruner、MMTok、MoB，再提出任务适配对已有代表基础的影响 |
| 5. 核心原则 | 为什么相关性以受约束更新形式进入 | 加入收益与移除损失，基础构建和条件修改各司其职 |
| 6. 实现与结果 | 原则如何落地、目前效果支持什么 | 实际双深度、QA 和渐进路径；同预算结果与明确指标 |
| 7. 贡献 | 三个可核对的新增点 | 具体视角/算法/证据，避免把每个组件单列为首次发现 |

注意力有二次计算项，但整个模型 FLOPs、KV cache 和时延不统一随 token 数平方增长；FFN/投影、访存和实现都会影响实际成本。不要照抄范文中不严谨的“所有成本都平方增长”句子。

研究缺口段候选：

> 条件多样性与多模态覆盖已经将问题需求纳入集合选择。然而，对已有视觉代表集合进行任务适配时，新候选的相关性收益与旧代表的移除代价并不对应同一组对象：前者评价候选与当前问题的联系，后者可能影响全部原始位置的代表质量。我们进一步研究，能否在保持入口容量的同时，将问题引导限制为对视觉代表基础的有限更新，使任务适配伴随明确的覆盖变化约束。

该段描述研究范围，不断言最近邻全部忽略删除后果。后续必须用最近邻对照文档核查是否仍有重叠。

机制过渡段候选：

> 基于这一考虑，我们先构建视觉代表集合，再以问题信号更新少量候选。对于每次一进一出的交换，我们分别计算原代表的移除损失和新候选的加入补偿，并仅接受覆盖退化受限的更新。基础选择确定视觉比较的出发点，条件更新决定如何改变这一出发点，后续渐进精炼则控制候选占用计算预算的长度。

贡献写法按机制文档第 8 节处理。“给出更新范围的分析”是合适的技术描述；不要把初等差分界描述成首个 VLM 输出误差理论。本文不以保证中稿或模拟审稿人认可作为贡献。

## Related Work：比较决策对象，不按年份堆论文

建议 3–4 段或小节，总量按页数控制：

1. **紧凑视觉输入与免训练选择**：PruMerge、VisionZip、VisPruner 与 AutoSelect 等，区分学习式选择、索引剪枝与表示合并。
2. **集合选择与问题条件化**：DivPrune、DART、CDPruner、MMTok、MoB；说明集合内部多样性、群体覆盖及问题目标各自评价什么。
3. **统一目标与受约束更新**：补查 SCoRe、CoIn、QCPruner；从目标、可行域、初始化和更新权限比较，不将“Query+Coverage”重新宣称为创新。
4. **深度与渐进删除**：SparseVLM、PyramidDrop、ViTCoP、FitPrune、VFlowOpt、STAR-Pro、CoRePrune。诚实承认阶段和集合条件的先例，再定位具体入口规则。

每段采用“这些方法完成了什么 → 当前方法在哪个技术对象上进一步研究”的关系。最近邻尽量给公式/算法定位；不能仅写“我们的机制更全面、更鲁棒”。

## Method：定义必须足以与代码一一对应

推荐结构如下，避免按内部文件名分小节。

| 小节 | 必须定义的内容 | 关键核查 |
| --- | --- | --- |
| 问题与预算 | I、Q、N、索引集合、K_l、W、文本长度；剪点前/后计数 | 最终 K、平均 K、W 分开 |
| 总体框架 | 选择依据、原始索引、实际输入表示与 Decoder 路径 | 选择特征不自动替换前向特征 |
| 视觉代表基础 | 深度、张量来源、融合、归一化、Native 目标与求解 | C1/C2，不能只留抽象算子 |
| 问题条件更新 | 问题有效位置、q、G、候选池、门控、目标、迭代、排序与停止 | C3，精确照生产配置 |
| 更新性质与含义 | 移除/补偿分解、有限更新界、具体解释 | 条件固定；不扩大成答案保证 |
| 渐进执行 | 真实 RDRIFT 公式、统计、各剪点规则、位置/掩码/cache | C4，不能从名称猜公式 |
| 复杂度与实现 | 完整视觉塔、projector、相似度与选择、prefill、decode | 不把 token-layer 当 FLOPs |

每个重要操作用同样的阅读路径解释：当前需要决定什么 → 哪些数据可获得 → 怎样计算 → 计算如何改变决策 → 该决策给下一步留下什么。需要概念解释，不能把整节写成代码逐行翻译。

参考实现的重要细节：原始 q 可外部传入，也可从投影视觉/问题 embedding 计算，两条路径互斥；总体标准差、torch.median 约定、截断和 sigmoid 应核实。默认没有 saliency guard；候选池在每次交换后重算。max_swaps 是上限，不是保证正好交换 8 个，也不是收敛判断。

### 算法与图的分工

伪代码解释完整执行：原图编码 → 实际选择描述 → Native → QA → 原表示按索引取子集 → Decoder 剪点处理。不要在算法中新增参考实现没有的全局目标、未来信息、J>0 条件或强制不重复加入规则。

框架图应至少区分：虚线的选择依据与实线的表示前向；Native 集合与 QA 的一进一出；覆盖门控；Decoder 日程。保留现有可编辑 SVG，按真实代码修订。可以加一个交换局部示意，让读者看清“新候选—被替换者—原始群体”的关系；构造示意必须标示为示意，不伪造真实样本热图。

建议短段落，回到受覆盖约束的任务适配，概括方法与当前结果。限制可具体到：当前验证范围、选择器成本、细粒度文字任务的取舍。暂不声称已解决视频、所有架构或所有预算。

候选正文：

> 本文研究严格视觉预算下的问题条件集合更新，提出以视觉代表基础约束任务适配的 BELA 框架。通过在同容量交换中同时评价加入收益和移除损失，BELA 将问题相关性调整与覆盖变化联系起来，并结合 Decoder 内渐进精炼控制后续预算。现有 LLaVA-1.5-7B 结果支持这一设计在固定日程下的综合性能收益。进一步工作可分析其选择开销、细粒度文字保留和跨架构适用范围。
