# 相关工作与允许的论文主张

核查日期：2026-10-26。本页仅列会改变当前决策的作者论文/仓库。公开预印本不自动视为已获顶会接收；没有在本机复现这些论文。论文分数不跨checkpoint、MME类型或预算语义直接排名。

## 1. 必须面对的已有研究

| 工作与原始来源 | 已有内容 | 对本项目的限制 |
|---|---|---|
| [STAR-Pro](https://arxiv.org/abs/2609.05916)、[官方代码](https://github.com/EasonAI-5589/starpro) | 融合前覆盖候选、融合后渐进精炼 | 两阶段、覆盖＋attention、日程本身均非新的主贡献；本地Sci/OCR异常需解释 |
| [AgilePruner](https://arxiv.org/html/2603.01236v1) §4、B.5、F.2 | 主方法复杂度调节选择偏好；附录也研究动态数量及细粒度推理失败 | 不把“erank不等于问题难度”认领为首次发现；不能说论文未做动态K |
| [QCPruner](https://arxiv.org/html/2609.19990v1) §3、Table16 | 利用交互后的query信号加权覆盖；受控比较多种集合后端 | 不宜称为纯pre-LLM入口法。其LLaVA默认先执行8个完整decoder block，不能把最终K64按W2048比较 |
| [CoRePrune](https://arxiv.org/html/2609.26484v1) §IV—V | 深度与删除集合条件可删性；ViT内渐进及交互后集合精炼 | 不只是叙事不同；条件删除和集合救援有直接先例，不作为新发现复述 |
| [E2S-Pruner](https://arxiv.org/html/2608.23253v1) §4.2、Table2 | head可靠性、LLM层间证据冲突与冲突保护 | 它并非我们的ViT入口guide，但“有分歧就保护”概念重叠明显；不能仅凭来源层不同建立创新 |
| [CoViST](https://arxiv.org/html/2609.33397v1) §3、D.5 | 跨压缩阶段继承贡献、位置、内容及元信息 | 共享状态、代表关系继承、后续压缩丢失上游信息均有近邻工作 |
| [CoverPruner](https://arxiv.org/html/2609.03158v1) §3 | 在projector空间做query需求加权的代表覆盖 | “相似不等于该如何保留、被删证据由谁代表”不属于空白 |
| [SAVER](https://arxiv.org/html/2610.16615v1) §3、§5.4 | 数据集及样本层面的相关性—多样性权衡 | 不能从MMB得分高推出全局覆盖机制；不同任务权重不同也不是新发现 |
| [PAA-Bench](https://arxiv.org/html/2610.24740v1) §4 | Dense正确保留、随机选择敏感性、真实成本 | 聚合均值与Token数不足以证明选择能力；采用这些评估时必须引用 |
| [CDPruner官方核心](https://github.com/Theia-4869/CDPruner/blob/main/llava/model/llava_arch.py) | 条件DPP及最终按ID排序 | 移植ID对照要保留原贪心顺序；额外文本塔与选点成本计入正式系统比较 |

这一表不是穷尽检索。不要把“CD/STAR/Agile没作为主claim”视为整个领域没人研究过。检索到近邻工作时更新区别与必要对照，而不是只改模块名。

## 2. 对用户转述方案的独立修正

- 任务分数向量出现取舍，不足以证明跨数据集稳定、显著的反相关特质；尤其不能直接宣称MME/MMB代表全局语义、GQA/POPE代表对象。
- L9的GQA收益接近CD，但POPE大缺口仍在；两者允许不同根因。
- “入口身份×后续删除”值得研究，但完整系统比较不是因果归因。固定入口容量/日程的CD64_L2与共享前缀剪点干预才提供更窄的识别。
- 永久survivor与最终K冲突；将其改成有容量上限、可以无动作、每次重新竞争的交换。不能用强保留改变真实W。
- 用修复后的时间表讨论效率，不继续传播失效计时。当前未给出新数值，本包不捏造。

## 3. 候选方法的区别与最强质疑

候选利用视觉深度guide产生的少量来源弱先验，研究入口的实际答案收益是否在后续低容量筛选中丢失，再用当前问题信号约束少量同K交换。它没有新ViT剪点、没有额外教师/CLIP塔、没有特征合并或attention bias，也不要求新的学习参数。

这些工程差异不是充分新颖性。局部代理仍属于已有coverage/相关性路线；跨层分歧保护已有直接先例。只有以下证据齐全才考虑把它写成主贡献：项目自己的答案级失效具有可复查的条件结构；删除前信号预测有用；负控/来源-only更弱；同预算和真实成本下稳定提高；跨模型具有边界清楚的迁移。

若只把几种已有评分相加后涨分，应按强基线或有限增量报告，不能夸成新的证据理论。若只有静态轨迹切换有效，也不能把它写成已解决动态证据生命周期。

## 4. 当前可写与不可写

可以写：在本地同协议历史结果中，guide改变导致任务取舍；L2低预算落后CD32均值；入口容量和后续存活分配存在机会成本；用户已报告旧延迟实现被修复。每项附结果来源。

需要新实验证据后才能写：入口补回的有效候选被后续筛选系统性抹掉；来源＋当前交互能识别并修复该损失；该规则优于随机、打乱和去掉显式query门控；95/98由单一真实配置达到。

不能写：两个任务组天生反相关；Stage1是唯一瓶颈；深层Token普遍有害；原始Patch未覆盖意味着对象信息消失；全程保留76个object Token仍为E3；代理单调保证答案准确；当前结果已全面超过今年方法。

CoViST的Table9在实际层平均约64.13时报告MME Total1863、MMB64.4。这不是本地公平胜负表，但足以限定我们只能说相对已跑CD/STAR拥有局部优势，而非领域领先。
