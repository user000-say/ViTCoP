# 方法定义、因果验证与对照

## 1. 本原型的地位

本原型把上一轮“少量跨深度候选准入＋有限后续机会”具体化。它不是已证明的新发现，也不把coverage、分歧保护或局部交换认领为首次提出。先导应判断这个定义是否值得保留；失败时删除它，不不断叠加新的评分模块。

全部在线选择仅使用当前合法得到的特征与问题信号；不使用正确答案、Dense分支、未来层、外部教师或额外完整LLM前向。离线反事实可以使用标签和高成本路径，但要单独记账，不能拿它们的耗时作部署结果。

## 2. 真实预算与剪点

| 名称 | 段内K×block数 | W | 视觉平方项Q | 真实剪点（1-based block完成后） |
|---|---|---:|---:|---|
| L2 | 64×12 + 17×8 + 10×12 | 1024 | 52664 | 12、20 |
| E3 | 172×4 + 120×8 + 24×10 + 16×10 | 2048 | 241856 | 4、12、22 |
| CD32 / COVER32 flat | 32×32 | 1024 | 32768 | 入口一次 |
| CD64 / COVER64 flat | 64×32 | 2048 | 131072 | 入口一次 |

Q只衡量视觉平方项，不是完整attention FLOPs，更不是延迟。实际序列还包括文本与特殊Token。默认主实验每个样本严格满足W；按样本浮动K后只满足均值的协议另列，不能混入本表。

L2前12层用掉768，后20层256；CD32相应为384/640。这是值得检验的机会成本，不证明“越晚保留越好”。E3前12层约花80.5%预算，综合分仍强于CD64，因此简单的预算前置解释并不充分。

## 3. 来源弱先验与入口准入

设原始视觉Patch总数N=576，现役Dual选择集合S0。两层guide分数为g9、gLate；分数较大表示该guide更偏好。先核对真实guide方向，不能凭变量名推断。

令R为同图所有N个Patch的平均秩分位数，相同分数保持相同分位，定义：

~~~math
 d_i = max(R(g9)_i - R(gLate)_i, 0).
~~~

这只是跨guide的正分歧，不能命名为“对象概率”。C9为归一化L9特征的余弦相似度截到[0,1]。入口未选候选的提案优先级为：

~~~math
 t_i = d_i [1 - max_{j in S0} C9(i,j)],  i not in S0.
~~~

W2048 b=8；W1024 b=2。最多换入b个正优先级候选。Donor来自S0中现役entry priority最低者；排除S0中最高b个已有正分歧候选。该entry priority必须由生产实际guide或COVER选点边际导出并记录来源，不能凭空发明一个“原生分数”。若使用COVER最终贪心边际，应在方法中明示。

排序、去重与tie-break确定性固定。实际候选不足时少换或不换，绝不复制Patch凑K。所有换入特征仍来自当前生产projector输入的同一层；L9用于选择统计，不自动改成把L9 hidden送给LLM。

随机准入对照：复用真实准入的donor与实际换入数量，从相同未选全集中抽取不同候选。主先导用seed17，晋级后29/43。若还需要匹配guide分数段，预先固定分桶规则并记录；不能看答案后选择随机池。

## 4. 每个剪点的有限交换

入口确定后，在该入口内按d选最多b个正分歧anchor，保存原始ID和d权重。无正分歧可为空。S-only在原Dual入口上使用同一定义；AS在有界准入后的入口使用同一定义。

在剪点l，V是当前真实存活集合，T0是原选择器输出的K个ID。p_i为当前V内原选择器分数的秩分位；u_i为当前问题词到视觉的真实交互效用在V内的秩分位。必须分别导出native score与fresh query utility，不能把历史drift直接当成当前query证据。query分数恒定时u置0，表示这个先导没有提供区分信号。

C9和CLate来自已经执行的视觉层，均截到[0,1]，设 Cmin=min(C9,CLate)。它仅表示“两个视角均认为可替代”的保守代理，不保证真正功能替代。原入口已被删除的anchor只作历史记录，不给它伪造当前attention，也不把它重新插回。

对当前仍存活anchor A∩V 定义局部选择目标：

~~~math
 F_l(T) = (1/K) sum_{i in T} p_i
          + lambda/b sum_{a in A intersect V} d_a u_a max_{j in T} Cmin(a,j).
 lambda = 0.25.
~~~

分母b固定为该预算的anchor容量；不因深层anchor变少而自动放大剩余来源权重。u的绝对幅度没有再被总和归一化抹掉。全部p、u、C在同一剪点的交换迭代中固定，下一真实剪点重取合法当前信号。

只考虑A∩V∖T中的少量候选；donor限定为T内native分位最低的最多max(4,2c)个，c=min(b,floor(K/8))。选择使F提高最多的一进一出，最多c次；没有正增益就停止。输出保留当前序列的相对顺序。E3三个剪点c=8/3/2，L2为2/1。它不要求某个来源永久存活，也不要求用满c。

CPU参考实现见tools/reference_selector.py。它是验证定义与边界的参考，正式GPU路径必须向量化候选×donor计算，禁止把hidden搬到CPU或逐候选调用item同步。只捕获需要的视觉层状态，不能为省实现工作把所有层attention长期保存。

可陈述的局部性质：每次接受的交换提高这个固定局部代理；K保持不变；输出是当前V的子集；动作数有上限。不能据此推出准确率不降、答案证据已被吸收或全局最优。lambda和有限搜索是研究设置，不是安全证书。该目标与已有coverage类目标存在直接联系，不单独认领其数学形式为新颖性。

若F9/CLate亲和关系未在生产中缓存，需要用已执行层的特征构建并计入选择器成本。不要新增ViT前向。捕获和构建成本不合适时可否决该原型，不能悄悄换成不同算法仍沿用同一实验ID。

## 5. 真正区分H1/H2/H3的反事实

选取随机图像总体，加上Dual独对、L9独对与CD独对分组。分组用于诊断，主成绩仍按总体报告，不只汇总精选成功案例。

(1) 固定K0及真实特征来源，进行少量候选交换，比较自由生成与官方得分。先问入口替换是否有答案价值。

(2) 对相同修改入口，在真实剪点前保存同一个prefill状态，分支仅改变本次删除的ID。按生产要求更新mask、position IDs、逐层KV及序列索引，随后真实生成。不能在剪掉Token后从另一分支拿未来hidden免费补回。

(3) 采用同donor、同净交换数的随机单剪点分支。tools/reference_selector.py中的matched_random_cut用于同一前缀，不能跨不同前缀强行恢复不在alive内的ID。若多步局部交换出现中间候选进出，随机控制匹配最终集合的净变化数，并同时记录总动作数。

(4) 定位哪些入口修复收益在L4/L12/L22（或L12/L20）之后损失。某路径保留更多Token且答得更好不是同成本胜负；它只说明该删除干预有影响。

H3所需证据：入口交换确有答案收益；现役后续选择会损失其中一部分；来源/问题条件交换能在同容量下挽回，并强于匹配随机、标签打乱及显式query门控移除。三步缺一时不写成完整跨阶段纠错机制。

Stage1-only 172全程W5504、L2入口64全程W2048，均非原方法同预算上界。关闭部分剪点的分支不能放进同成本主表；其作用是因果诊断。

## 6. 主要消融与负控必须匹配

| 对照 | 精确变化 | 解释范围 |
|---|---|---|
| Native | 原入口和原剪点 | 锚点 |
| A | 仅有界准入 | 入口变化 |
| S | 原入口＋有限交换 | 后续修复；可能结构性无动作 |
| AS | 准入＋有限交换 | 最终主候选 |
| RAND | A的相同donor/实际数量，随机准入；无guard | 匹配A，不能单独作为AS的完整随机对照 |
| RAND_AS | 同RAND，启用同一个guard函数 | 匹配AS的准入扰动 |
| SHUFFLE | 与AS相同入口，一次打乱入口风险权重，跨剪点固定 | 来源信息是否有效 |
| SHUFFLE_S | 无准入，与S匹配的打乱 | 匹配S |
| SOURCE_ONLY_AS/S | 匹配胜者但u=1，移除显式query门控 | 是否优于一概按来源保留；native仍可能含query，不能称完全image-only |

SOURCE_ONLY是确定性消融，只跑主seed；不要把同一确定性配置换3个seed重复测当稳定性证据。随机与shuffle才使用多seed。若动作量分布差异很大，补上共享前缀同净交换数的随机单剪点诊断，避免把动作数量误认成来源识别能力。

如果论文要强调Cmin而非CLate是关键，再做同入口/同query/同K只把Cmin换成CLate的受控先导。未做这一项，不能将保守多视角亲和定义单独列为核心贡献。

A/S/AS的指标交互项可以报告，但POPE F1非线性，且交互依赖尺度；不要用“必须超加性”筛选故事。动作率、来源有效性、真实输出收益比一个正交互项更有说服力。

## 7. 最强反对理由与失败范围

候选跨深度分歧可能是噪声；亲和关系仍不能代表答案可替代性；query分数也可能被删除或文本模板扭曲；源权重可能保护冗余候选；低预算下一个名额的机会成本很高。所有这些都能使代理F提高而答案下降。

若A有效但AS不优于A，保留A并停止声称后续保护必要。若AS与SHUFFLE相当，不保留来源传递主张。若SOURCE_ONLY相当，不能把当前query验证写成必要机制。若当前候选对POPE无作用、只改善GQA，报告任务边界并根据FP/FN定位POPE，不能统一解释为对象缺失。
