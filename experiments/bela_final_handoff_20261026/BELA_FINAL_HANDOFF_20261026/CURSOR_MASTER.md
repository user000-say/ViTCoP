## 3. 不接受的预设与必须纠正的方案

1. 当前观察是任务表现的取舍，尚不是统计显著的“反相关任务特质”。MME/MMB包含多类能力，不能把它们直接命名为语义轨，把GQA/POPE命名为对象轨。
2. L9使GQA+0.91，但POPE只有+0.25；不能据此宣布两者主要瓶颈均在入口身份。POPE需要单独看FP/FN、yes-rate及三个子集。
3. STAR的Sci/OCR低分可能受执行或评测影响，不能反推“渐进一定救不了弱入口”。
4. 76个候选若永久不删，就无法装进E3最后16个名额，更无法适用于L2最后10个。双轨集合还必须去重，172不能只在纸上相加。
5. N64-FLAT与E3虽可同W2048，入口容量分别64和172，生命周期也不同；它比较整体策略，不能单独归因Stage2。CD K64身份不能填充或复制成“纯CD K172”。需要严格身份对照时，真实运行CD的K172选择，标清它只是诊断。
6. “保护到第12层”对首次就在第12层剪枝的L2是空操作。W1024的有效后续干预必须在64→17或17→10处发生。
7. Stage1位于完整ViT编码之后、LLM之前；它没有在进入视觉塔前剪枝。当前不增加ViT内剪枝主线。
8. 不要求两个阶段的得分交互项必须显著大于零；不把超加性当作机制成立的必要条件。

## 4. 研究主问题与竞争解释

**主问题：入口候选的答案价值，是否在后续极窄的存活集合中被系统性丢失；这种损失能否在删除前被现有来源及问题信号识别？**

它是可证伪的假设，不是已发现的新规律，也不预设别人没研究过相近问题。

保留四种解释：H0剩余实现/协议差异；H1入口缺少有效候选；H2入口足够但后续选择失效；H3入口构造与后续删除准则不匹配。任何一个都可以被结果支持或否决。

核心验证链：固定数量入口交换改善自由生成答案 → 固定前缀、同容量剪点干预检查收益是否丢失 → 用删除前可用信号预测与修复这部分损失。仅有Patch ID覆盖率、attention热图、KL接近Dense均不足以建立这条链。Dense也可能答错，应同时报告全体样本的得失。

具体执行和数学定义见 docs/METHOD_AND_CONTROLS.md。

## 5. 唯一主候选：有界准入 + 同容量剪点交换

不建立固定的任务轨，不让某来源拥有永久豁免权。

- Stage1先执行现役Dual COVER。W2048最多替换8个，W1024最多替换2个，使用L9与late guide的正向排名分歧及L9未覆盖程度提出候选；送入LLM的实际特征层不变。
- 保存原始ID、两层guide分歧、固定小规模anchor状态。它们只是可验证的弱先验，不是对象标注或真实删除风险。
- 每个真实剪点先得到原生产选择器的K个ID；仅在当前仍存活的少量anchor候选中，依据当前问题信号和保守替代关系，尝试同容量的一进一出。
- 本次最多交换 min(b, floor(K/8)) 个；没有正代理增益就原样返回。E3三个剪点上限分别8/3/2，L2分别2/1。下一剪点重新判断，不永久保护、不恢复已删hidden state。
- CPU参考式lambda固定0.25，第一轮不扫描。若只有调大权重/名额才有收益，必须先解释原型的动作率、代理与答案关联，不能无限扫超参。

该候选仅在入口/剪点答案级先导支持后晋级。基本的来源信息、coverage、局部交换本身已有先例；创新只能来自本项目独立发现与有效机制差异。参考代码是可运行定义，不是已验证最终方法，也不能拿CPU版本测GPU延迟。

## 6. 第一批：W1024五臂与W2048配对分析并行

| 臂 | 入口 | Decoder轨迹 | 目的 |
|---|---|---|---|
| L2_NATIVE | Dual K64 | 64×12→17×8→10×12 | 修复版本锚点 |
| CD32_FLAT | CD K32 | 32全程 | 同W强基线 |
| COVER32_FLAT | Dual K32 | 32全程 | COVER的固定入口能力 |
| CD64_L2_NATIVE | CD K64 | 原L2选择器 | 固定L2日程替换入口 |
| CD64_L2_STATIC | CD K64 | 按DPP原始贪心顺序保留17、10 | 固定入口和容量替换后续规则 |

五臂W都为1024。先用同一执行后端、相同真实输入特征与位置策略，CD仅提供ID；官方完整CD路径另作系统对照。确认统一路径复现对应掩码后再比较。导出DPP排序前的贪心序列，不能从最终按空间排序的ID取前17个。

解读：CD64_L2_NATIVE−L2隔离同容量入口策略影响；CD64_L2_NATIVE−STATIC隔离固定入口/日程下后续选点规则影响。FLAT−L2同时改变入口K及生命周期，属于整体策略比较。STATIC−CD32在共同DPP嵌套顺序下，检查“更多早期候选换更少后期容量”是否值得；要先验证DPP K32确实与K64贪心前缀一致，不能假定返回数组嵌套。

W2048首轮复用/小样本核对E3 Dual、L9-only、CD K64的预测，定位L9独有正确与Dual独有正确。COVER64_FLAT仅在需要验证整体策略时开启；CD172_E3仅在确实需要同入口容量的CD身份对照时开启。二者不默认全量。

## 7. 样本、输出与先导设计

先按image_id固定清单：GQA约256张图及相应问题；POPE约256张图及这些图的全部正负、三个子集问题；TextVQA约128张图；MMB约128张图。主seed=17。先测20条真实样本估计耗时，样本量按image统计，不把256张图误计成256个问题。

先导清单在看新变体结果前冻结。已有全量榜单已反复曝光，不能重新切一部分就称从未使用过的独立确认。记录曝光历史；之后冻结算法，不再按完整测试分选超参。优先保留一个未参与选型的backbone作外部确认。

每项输出 predictions.jsonl、metrics.json、run_meta.json、必要的cut_trace.jsonl。run_meta至少包含commit、checkpoint、scorer/prompt/IDs哈希、实际W、真实剪点、attention backend、precision和延迟修复版本。记录每个剪点原始ID、实际交换数、候选来源、当前query得分、代理前后值和动作耗时；全量正式计时关闭大trace。

GQA/MMB/Sci采用官方逐题得分；TextVQA保留官方软分。POPE保存原输出、官方解析后的0/1预测、valid、label和split，明确pooled F1或子集F1平均。invalid不能悄悄变成“no”。MME采用官方成对问题与复合计分，不能把所有行当独立准确率平均。

tools/paired_analysis.py按image聚类重采样，POPE每次重算F1，TextVQA不二值化；MME必须走生产官方评分。先导CI很宽时扩一次固定样本，而不是把“不显著”直接当成无效；也不能只展示被选中的成功案例。

## 8. 机制门禁：何时实现、何时停止

runtime_bound：真实接口已定位，修复版本及样本/评分协议已记录，最小smoke可运行。窄核验通过就继续，不开展宽泛长期审计。

mechanism_1024 / mechanism_2048：至少完成对应预算的候选答案级交换或剪点干预，存在可复查的修复线索。来源不明确但五臂有明显入口差距时，先做针对性交换，不把该差距直接当H3成立。

通过后，运行本预算五个先导：A仅准入；S仅剪点交换；AS组合；RAND同donor同实际替换数的随机准入；SHUFFLE在AS相同入口上一次打乱来源权重。S在原Dual入口上构建同定义anchor；若没有正分歧或从不动作，标记结构性空操作，不伪造2×2有效消融。

初筛参考：GQA约+0.5或POPE约+1，并且另一弱项及Text/MMB无明显损失。它只是决定是否扩大样本的资源规则，不是论文成功门槛。小样本效应、动作率和配对区间一起判断，不机械依赖单一数值。

若AS晋级，追加同guard的RAND_AS与匹配SHUFFLE，不能拿“随机准入但不启用guard”对照AS并声称完全排除随机效应。若S晋级，使用无准入的SHUFFLE_S；若A晋级，用RAND。AS/S胜出还要做匹配的SOURCE_ONLY，移除显式query门控，检验是否只是泛化的来源保护。随机负对照seed为17/29/43；可复用已完成的匹配seed17。确定性的SOURCE_ONLY只跑主seed。

淘汰原因写具体：没有可恢复的答案收益；收益与随机相当；来源打乱不影响；代理改善与答案无关；交换挤掉OCR/其他有效候选；计时成本破坏前沿。无动作首先检查定义与真实评分调用，不能通过放大保护数硬制造效果。

条件未通过的分支停止，资源转到有效单模块、必要强对照、确认或外部模型；不因为有空卡恢复盲扫。

## 10. 准确率晋级与最终版本选择

两预算分别选择胜者，不能强迫每个预算启用相同数量的新动作，但必须共享同一清楚的方法定义。主表每个预算是一套真实配置的全部任务结果，不逐任务选择不同方法。

W1024：首先正面超过CD K32=94.41并向95推进，GQA/POPE缺口明显收窄，MME/MMB/Sci/Text不靠大幅牺牲换均值。W2048：向98推进，GQA/POPE至少保持对当前强基线的竞争力，同时避免L9-only的MME/OCR损失。未达目标如实报告，不改参考值、不改预算定义。

将Text/MMB约0.3分退化作为复核触发，MME同时看分项与Total；这些不是可任意消费的“损失额度”。性能区间、反复计时噪声及任务重要性必须一起看。新增TTFT/Fixed32若超过修复版锚点约3%，必须有真实前沿收益；只因名义W相同不能忽略选择器成本。

最终分支：

- AS稳定胜出且负控更弱：保留具体来源传递与同容量纠错。
- 只有A或S有效：只保留有效部分，不强造“两处都新”。
- CD入口移植有效但本候选无效：它是强诊断/强基线，不把CD模块改名当贡献。用原始证据说明入口信号问题，停止宣称本候选解决了跨阶段误删。
- FLAT不弱于staged：承认当前多阶段收益不足；不继续把渐进当必要结构。
- 全部无稳定改善：冻结已验证基线与失败发现，缩小论文主张；不得声称95/98已经可达或核心方法已经成立。

## 11. 论文深度与必要交付

科学深度由“可定位失效—合法信号—受控干预—可部署修复—边界”建立，不以模块数量或公式复杂度衡量。要区分：任务均值取舍；真实同图不同问题需求；具体候选的可替代性；后续删除带来的条件损失。

机制图必须包含随机抽样、得与失及失败案例。POPE不存在对象的样本没有一个必然可框出的目标Patch；若主要修复FP，应讨论干扰与语言倾向，不能全写成找回小物体。GQA和POPE允许通过不同作用环节改善，不强迫共同根因。

先画三张核心图：两预算的六任务收益向量；同一入口修改经过各剪点后的答案收益变化；来源/当前问题/同容量交换及打乱负控。最后增加准确率—当前TTFT/Fixed32前沿。不要把“不同数据集分别由不同轨服务”预绘成已证事实。

必须交付：真实源码diff及开关；RESULTS_MASTER中六任务与来源；逐样本配对/POPE confusion；实际逐层K与动作率；A/S/AS及匹配负控；当前时间表；一个未参与选型的模型或清楚说明缺失；可审阅的Method/实验/局限草稿。至少争取一个有结构变化的额外backbone，不以复刻STAR七模型为硬指标。

Related Work和实验协议现在写；10月29日开始正式CVPR模板整合。最终Method、标题与Abstract成果句按胜出实现重写，不能把没晋级的原型留在核心贡献里。若只提高ACC而新颖性仍不足，应明确写“性能已改进，投稿贡献尚未闭合”。

## 12. 实际使用本包

先读本文，再读 docs/METHOD_AND_CONTROLS.md 和 docs/ADAPTER_CONTRACT.md。

~~~bash
python tools/check_plan.py
python -m unittest discover -s tests -v
python tools/run_queue.py --phase pilot --output /path/to/new-run/pilot_preview.json
~~~

Cursor在服务器创建真实adapter与bindings/gates，随后直接运行合法阶段；不需要额外询问用户是否继续。

~~~bash
python tools/run_queue.py --phase pilot --bindings /path/to/bindings.json --gates /path/to/gates.json --execute --wall-hours 10 --output /path/to/new-run/pilot_ledger.json
~~~

pilot阶段把低、高预算先导交给同一个四卡调度器；不要同时另开同卡队列。若使用现有exclusive系统，把本包job列表映射进去即可，不要为了使用备用runner重写现有基础设施。阶段间继续candidate/controls/confirm/ablation，条件与胜者记录在gates。external模型与独占计时复用生产评测入口，不把它们伪装为已由本地备用runner验证。

本包28个arm定义包含现有锚点、诊断和负控；并非要求24个新模型全跑六任务。唯一主算法候选始终只有A/S/AS所描述的一套条件机制。
