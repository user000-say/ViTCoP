# BELA / ELVA — CVPR 2027 科研决策书（2026-10-22）

> **证据级别**：本文件整合本次实际上传的 `上传包.zip`（两份 E001–E014 历史聊天、E014 源码快照、组会 PPT）与 `chatgpt-export_CVPR研究规划 ...txt`（47 轮研究讨论和后续结果），并核对所列近期原始论文。历史会话里的成绩是“报告值”，不是本轮 GPU 复现；附件**不包含服务器上现役 BELA 代码、全部原始预测及全部评测器**。任何自称服务器已经通过的结论一律无效。

## 0. 科研立场：目标是投稿，不是维护某个已起名的模块

我们必须按 2026-11-10 AoE 完成 CVPR 2027 注册、2026-11-16 AoE 提交全文（官方 CFP）。Paper story 可以微调，但是每个新增算法都必须给出：明确的模型损失假说 → 受控干预 → 最强固定/随机对照 → 全量评测 → 真正的执行开销。

我选择的**候选**论文问题是：
“复杂图像并不必然需要更多 Token，应该用视觉证据的*剩余覆盖需求*决定入口预算，再根据早期图文交互信号决定这笔计算应消耗在较宽的候选集合还是较长的证据存活上；在同一**平均**预算下改进准确率与延迟的 Pareto 前沿。”

不是把‘图像复杂度高=一定需要多 Token’写为定理。重复前人的固定阶梯、自适应 K、普通跨层 Attention 不构成 CVPR 级别的新颖性。下面是可证伪的原型，不是已证实的最终 BELA。

## 2. 最近论文改变了什么判断？

### QCPruner (arXiv:2609.19990, 2026-09-17)
- LLaVA-1.5-7B 实验：保留64个图像 Token，GQA=60.8 / POPE=86.7；32个时 GQA=59.6 / POPE=86.4。
- 特别重要：同论文附录 *固定候选池、提示锚点、剪枝位置和预算* 的对照中，普通 Top-K 在 64 Token 已达到 GQA=60.8 / POPE=86.2；因此不能把 BELA 全部差距归因于 QCPruner 的加权覆盖公式。
- 它的目标权重和候选代表权重相辅相成；强调“视觉覆盖 ≠ 问题证据覆盖”。但该方法的 MME Dense 参考与我们的历史记录不一致（它报告1506.5，而本项目 R4 用1852），须核对 scorer、Prompt、任务实现。**不要移植其 Facility Location 目标当作创新。**

### STAR-Pro (arXiv:2609.05916, 2026-09-05)
- 已有“视觉覆盖候选+跨层文本注意力渐进退出”。与目前 BELA 的视觉入口/交互两段故事直接重合。
- 在 LLaVA-1.5-7B 对应 layer-average T=64/32，论文报告很强的任务保持，附录还证明入口候选倍率不是越大越好。
- 官方代码可用；应该同机同评分器复核，不得只对比论文上的速度。
- 学习点：关键不是多留更大的 K0，而是证据覆盖质量、多久让它交互、选择器的执行开销三者的耦合。

**CVPR 2027 近同期政策**：官方 CFP 指出 2026-09-15 后公开的成果一般按同期工作考虑，但任何实际影响本投稿的方法都必须明确引用和讨论；不能利用日期规避 QCPruner 或 CoRePrune。STAR-Pro 发布较早，正面比较的必要性更高。

### CoRePrune (arXiv:2609.26484, 2026-09-23)
- 单点 Token 排名无法表示同层共删集合下的可删除性；跨层删除效果也会变化。
- 学习点：诊断“一组低 Attention 的对象证据被同时删光”的失败场景。**不采用它的逐候选扰动+集合恢复作为新模块**；E014/CABS/ICER 的成本教训已经很明确。

### AgilePruner (arXiv:2603.01236)
- 图像特征分散程度可能调节注意力、多样性选择器的适用性；多样性不等于少幻觉。
- 学习点：复杂度应该**先预测增量预算收益**，而不是作为一定扩 K 的充分条件。

### E-AdaPrune (arXiv:2603.05950), OccamToken (arXiv:2605.29657), ET-Prune (arXiv:2608.01979)
- 动态入口/自适应预算、问题相关阈值以及文本密集图像的动态证据保护已有前人工作。
- 因此，“按复杂度调 K0 + 逐层减 K”**本身不够新**。我们的新增机制若成功，必须体现“已有 COVER 的未覆盖质量是否预测实际收益、且能和交互时长预算协调”，并与 SVD 有效秩、Attention 熵、随机预算做对照。
- 当前代码选择 COVER residual curve，是低成本、可与现有选择器共享中间量的一个**实验假设**，不意味着已优于有效秩。

### Information Horizon / Hi-Lo Prune (CVPR 2026)
- 浅层/深层视觉证据保留价值差异，以及在删除前进行交互/吸收，已有充分相关研究。
- 学习点：保留身份、保留时间、保留集合必须被拆分验证；不能从 Attention 波动声称因果信息转移。

## 3. 瓶颈的当前优先判断（主观排序，不是成功概率）

1. **问题尚未定位的入口损失**：COVER 可能保留了分散的背景，却遗漏某个问题的关键对象或小字；高复杂度图像可能大部分只是无关背景。因此仅根据 feature diversity 分配预算可能失败。
2. **入口容量—交互时长不匹配**：Stage1 172、第一次很早丢到90，可能把计算浪费在尚未完成图文融合的候选上；但历史 Wide/Short 等负面结果提醒不能默认延迟删除有效。
3. **RDRIFT 不是未来删除风险**：`now-old` 的 Attention 变化可能反映可见 Token 数和归一化的变化，不直接测真实答案贡献。
4. **时间/选择器开销**：已有 ICER 同预算提升有限而延迟明显增长；新方法必须只复用已存在的 COVER 相似性与 QED/RDRIFT 得分，而不是每个 decoder layer 重算 N×N。
5. **评分口径**：GQA、POPE 的绝对分数确实落后部分强论文，但 QCPruner 同条件普通 Top-K 已很强，表明骨干接线、剪枝位置、评测实现可能比新 selector 公式更重要。

## 4. 本轮选择：先做“预算需求预测”而非“任意复杂度阈值”

### Stage1 的诊断信号——COVER residual

在原始 576 个视觉 patch 特征中，沿当前 COVER **真实贪心加入顺序**得到前缀 S_k，定义

r(k) = (1/N) sum_i [1 - max_{j∈S_k} max(0,cos(f_i,f_j))]。

使用 k∈{16,32,64,96} 的残余覆盖量作为难度代理。它不是互信息、Token 因果效用，也不包含问题信息。越难覆盖，**可能**需要更大候选池。代码中的探针权重只是冻结初始值，用于尽快证伪假设。

若现役 COVER 非贪心或不同 K 的集合非嵌套，使用 `coverage_difficulty_from_sets` 按实际 K16/K32/K64/K96 选择集合计算各自覆盖残差，禁止用排序后的空间 ID 充作真实选点前缀。多次选择会增加算子成本，**首先只能离线验证信号**，上线必须复用中间相似性/索引并实测时延。

**核心测量**：同图像、同问题，低/高 K 或低/高 W 的真实 accuracy / teacher-forced loss 差异，是否随 r(k) 增大而增大？若相关性不显著、错配随机分配不输，则不得升级为主模块。

警告：上传 E014 原 `FIXED_COVER` 使用外部 E013 helper，现有源码中输出可能只是按空间坐标排序的最终集合。**不能把这种排序误当成贪心顺序**！必须在生产 COVER 内曝露真实 addition order，或通过不同 K 的真实运行恢复集合曲线并另行计算。

### Stage1-2 协同：单样本的 W 档位+固定入口/交互配比

离线原型（均为 32 decoder blocks、剪枝发生在 post-block4 和 post-block12）：

| 状态 | K0 | Kmid | Kfinal | W |
|---|---:|---:|---:|---:|
| EASY | 96 | 64 | 32 | 1536 |
| NORMAL | 160 | 96 | 32 | 2048 |
| HARD | 172 | 154 | 32 | 2560 |

若三档比例恰好 25% / 50% / 25%，名义平均 W=2048；**测试集并不保证这些比例**。必须用无标签 DEV 冻结阈值，报告每个任务、每种问题类别和总样本的**真实平均 W**。公平比较时，随机分配与打乱分配对照必须保持**相同实际 W 的直方图**。如果某个测试任务平均 W 显著超出目标，不能宣称同预算胜利。

为什么不直接上 QK 分类器？因为 E001 的算子税，及 E-AdaPrune/AgilePruner 的已有工作。先验证 image-only 信号是否预测预算收益，再考虑低成本问题条件化。

### Stage2：在线决定“较宽但较早删”还是“较窄但较晚删”

在第一次剪枝边界处，从真实 RDRIFT 已产生的同原始 patch ID 文本注意力，计算两个时间点 Top-rank 集合的 churn。这个量是**诊断代理**，并不直接证明答案损失。早期 churn 大则倾向保留更宽的中间候选至第12层；churn 小则选择更窄的中间集合保留至第20层。

对于每个上表的 W 档位：
- 后次边界 cut2=12：Kmid 分别为64/96/154；
- 后次边界 cut2=20：Kmid 分别为48/64/93；
- 这两种日程在每个样本上 **W 完全相同**，且最终都是32个 Token。

**重要**：这个二元 online 决策只有在现役模型已经暴露**低成本、同 ID、同 question mask**的早期 attention 时才允许开启；否则保持 post12 固定日程，**不允许为了获取 churn 增加逐层完整 attention 显式输出**。`early_drift<0.40` 选择 cut20 是待检验、未调参的示例阈值，绝不能写成定理或已验证最优常数。

## 5. 先做的实验，而不是一口气上多个模块

### Gate P0：恢复最强固定锚点
- 现役 RDRIFT 172→90→32、W2048、GQA/POPE 全量，确认 57.84/83.31 是否可复核。
- Stage1 ID、真实两次剪枝 ID、完整版本哈希；三类 POPE 的 FP/FN/Yes-rate；同机 TTFT。
- 官方 STAR-Pro 以论文对应脚本运行一次匹配 T64；强近邻只用相同 benchmark/scorer/硬件比较。

### Gate G1：同 W=2048 的静态容量重分配
- F1：172/90/32，cut4/12（冻结）。
- F2：160/96/32，cut4/12。
- F3：128/64/32，cut8/16。
目的：判断当前入口容量及短暂交互是否被错误分配；**F3 同时改变入口和剪枝时间，只能视为配方对照，不能单因素归因**。若 F2/F3 均更差，就不要假定“入口缩小、交互变长”一定好。

### Gate G2：真正按图像需求动态分配 W
- A0：无标签 DEV 标定的 EASY/NORMAL/HARD 档位。
- A1：在同批图像之间**随机打乱 A0 的预算档分配**，严格保持各档数量、平均 W。
- A2：固定平均预算附近的最佳静态配方和随机预算对照。
- 报告：整体 GQA、POPE，GQA 问题类型、POPE FP/FN、9任务 R9、图像复杂度分桶，真实平均 W 和 TTFT。
如果 A0 没有在相同实际 W 下可靠超过 A1 和最强固定点，则**停止复杂度主线**，不让“动态”留在最终方法里。

### Gate G3：再决定是否启用 Stage2 adaptive
- A3：固定 Stage1 容量和预算档，只让现役 RDRIFT 的早期 churn 决定 cut12/cut20。
- A4：保持 A3 的 cut12/cut20 **每一预算档内的分布**，打乱哪个图像进入哪个日程。
- 若 A3 相对 A4 的配对提升无证据，Stage2 保留冻结日程，专注已有 RDRIFT 问题相关选点即可。
- 若 A3 胜出，才研究能否把 Stage1 复杂度与 Stage2 churn 形成统一证据分配的正式模块。

### Gate G4：论文证明需要的其他实验
- W1024（平均 32）高压缩工作点；这档 POPE 损失很大，不能回避。
- 对比 STAR-Pro、QCPruner、CoRePrune 真实公平设置；QCPruner 的 32/64 最终保留数不是 layer-average T=32/64。
- 至少一个不同 backbone 或视觉证据类型；至少可复核的 paired bootstrap CI、真实 TTFT/Fixed32。
- 与 image effective rank、CLS Attention entropy、随机复杂度标签比较，以排除仅仅换个阈值指标。

## 6. 成立/否定条件（截止日压力下的止损）

- **保留 Stage1 动态**：在冻结 heldout 中，A0 在同**实测平均 W**与相近延迟下领先匹配随机分配/最强固定；且至少 GQA/POPE 中有清晰的弱项改善，其他关键任务没有严重退化。
- **否决 Stage1 动态**：A0 与 A1 同档，或复杂度指标不能预测“额外 W 挽救错误”的效用；即使图像复杂度相关性图好看，也不能写为创新。
- **保留 Stage2 动态**：A3 相比 A4 存在可复核配对优势，不需要额外 full attention / GPU 同步 / 显著额外 TTFT。
- **否决 Stage2 动态**：不同样本没有可预测的早/晚优势，或者额外 controller 实际更慢。
- **保留或去除 RDRIFT 新修复**：只有证明改善来自真实 Patch 保留而非 Yes-rate 改变，且开销没有重蹈 ICER。
- **始终提交论文**：若动态机制失败，则以真实最强配置及明确局限性完成投稿，但不能虚构动态模块效果或宣称通用性。

## 7. 推荐论文叙事（仅当相关门槛通过时）

可能标题方向：“Input-Adaptive Evidence Admission and Cross-Layer Lifetime Allocation for Training-Free VLM Compression”。
核心技术贡献须证明：`原始双层 COVER 视觉覆盖剩余需求 → 预测追加预算的边际收益 → 文本交互阶段将计算分配至合适的证据存活深度 → 实际 Accuracy–Latency 优于现有强点`。任何一环失败则收缩主张。

不要用绝对信息论名词包装简单 cosine/attention 代理。不要把最好的 GQA、最好的 POPE、最好的 MME 从不同方法臂拼到一张“完整方法”表。不要用视觉 Token-layer 节省比例冒充真正的 FLOPs / end-to-end speedup。
