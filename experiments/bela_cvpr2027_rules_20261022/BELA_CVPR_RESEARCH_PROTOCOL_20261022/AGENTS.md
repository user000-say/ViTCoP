# BELA / ELVA — CVPR 2027 研究治理协议（2026-10-22）

## 唯一项目目标
按 CVPR 2027 官方截稿时间完成一篇有实证竞争力、创新点清楚、真实高效的视觉 Token 剪枝论文。投稿是硬时间约束；创新、准确率、实验真实性与延迟同样是硬质量约束。不得为迎合用户、Cursor、审计 Agent、导师或既有故事而改算法。

## 不可违背的六项准则
1. 四项关键基准：GQA（Accuracy）、POPE（必须区分 F1/Accuracy）、MME（需核对评分范围）、MMBench-EN；同时给出单项原始成绩、Dense 对照、误差区间与 R4。目标是共同增强，而不是用平均值掩盖 POPE/GQA 下滑。
2. 结构逻辑与消融：每项模块都需独立贡献、同预算消融、替代方法、负面案例；Stage1 × Stage2 至少二因素交叉对照，解释入口证据如何影响后续保留/释放，杜绝概念拼装。
3. 故事与创新：明确已经由 STAR-Pro、QCPruner、CoRePrune、Information Horizon、AutoPrune、AgilePruner 等做过什么；不把名称、组合或调参当作新颖贡献。先证据再故事，反例必须保留。
4. 效率：报告 Token-layer W、实际物理序列长度、完整 prefill、TTFT、选择器开销、GPU memory、generation latency、设备/精度/批量；禁止把 W 降幅写成全模型 FLOPs 或真实提速。
5. 独立批判：对任何来自用户、审计 Agent、Cursor、文献乃至自己上轮的建议均列出支持、反对和可证伪预测；不以“专家建议”代替证据。不因一句话换方向。
6. 投稿交付：代码 commit/hash、数据版本、评测器与命令、预测结果、消融、论文图表、相关工作及截止时间同时推进；失败的假说及时停损，但保持提交准备。

## 每轮研究的强制输出（可按任务规模合并，不能跳过关键项）
A. 当前证据盘点：历史记录 / 原始日志 / 已复现 / 文献报告分级，指出缺口。勿把旧对话数字称为本轮复现。
B. 文献更新：优先论文原文、附录、官方代码；逐项核对模型、checkpoint、指标、预算、剪枝层位、论文发布日期和实际实验条件；来源网址入日志。
C. 竞争性假说：至少一种主假说及一种反假说；解释为何该实验能区分。
D. 数学和工程检查：用 Python 验证预算 W=ΣK_l、层数和整数约束；检查 patch ID、KV-cache、position IDs、attention masks、prefill/decode 协议；数值复算及反向核验。
E. 实验排序：优先信息增益高、代码风险低的受控实验；列出预期分叉、判断依据、止损条件；禁止超参数无限扫描。
F. 审稿视角：一句话讲清真正贡献、最近前人冲突、当前最强反证；若不具备论文价值要明确反对。
G. 本轮交付：明确完成/未完成、适用代码版本、可运行测试和后续 Cursor 单条执行命令；绝不宣称未跑的 GPU ACC/TTFT 已完成。

## 实验口径红线
- “88.9%/94.4% 压缩”在 BELA/STAR-Pro 分层设置中仅可指 (1-W/(576*32)) 的视觉 Token-layer 代理预算；不能与单次最终保留 64/32 的论文直接等同。
- POPE 必须注明 F1、子集、答案解析；MME 与外部论文存在 Dense 参考值差异，核实前不比较绝对总分。
- 有多个候选/参数时，开发集决策、固定确认集测试，防止只报告最高结果。
- 对深层“随机剪枝不差”的论断，以固定 W、固定剪枝边界、固定末层 K、多随机种子为检验，不外推成所有任务/模型均应随机。
- 对动态图像复杂度预算，以相同样本平均 W 和相同预算直方图的随机打乱对照验证其预测能力；额外控制器延迟必须计入。

## 代码与安全纪律
- 没有服务器当前工程就只提供可运行的离线模块/诊断方案，不伪装为现役代码修改。
- 涉及 Decoder 中途物理移除视觉 Token，必须先通过 smoke tests：图文 token 对齐、位置编码、KV 长度、批大小、连续生成、FlashAttention/SDPA 兼容性。
- 保存原始每题预测、时间分布、每层 K/ID trace、commit 和 config；所有主表自动从日志汇总。
- 用户的研究判断不能高于结果；本文件同样可被新证据推翻，但必须记录变更理由。
