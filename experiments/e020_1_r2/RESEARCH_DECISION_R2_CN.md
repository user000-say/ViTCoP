# E020.1 R2：独立研究裁决与修订依据

日期：2026-10-16。已完整阅读用户本轮上传的审计文档，并审查当前工作区 E020.1 的算法、采集、拟合、诊断与执行器。本轮没有服务器仓库、真实训练数据、GPU或新ACC/TTFT。审计中的评分是主观评价，不能当作方法有效性或投稿概率。

## 1. 我的判断：修改E020.1，保留研究问题，收紧部署策略

当前最有依据的现象是入口与日程的性能交互；最关键的未完成项是监督式集合交换是否带来真实增量。E020.1应继续，而不是新起算法编号。但原默认执行方式存在可以直接定位的错配，必须修正后再判定方法。

我接受审计关于“核心分支长期未闭环”“缺S0和真实成本”“需正面对外比较”的意见。以下三点不照单全收：

1. **不按日期或一次未涨分直接判算法失败。** 截止日期可以限制资源投入，不能决定科学解释。先区分候选动作没空间、NLL与任务不对齐、预测学不会、部署成本抵消收益。达到完整负证据后才停止对应分支。
2. **不把入口×日程交互预定为论文主贡献。** 这是同一评测上发现的现象，可能主要由MME、选择器边界和容量阈值解释。若独立确认后消失，应从主故事中撤下；不能为维护审计认可而保留。
3. **不把“学习失败后用最佳固定日程”当成已有CVPR保底。** 固定配置有实验价值，但若没有新机制或外部优势，它仍不足以自动支撑主会论文。

也不应为了证明独立性而否定合理建议。判断标准始终是能否以更少的混淆得到更有信息量的结果。

## 2. 当前结果能支持什么

用户已报告：COVER NEXT 96.67、SHIFT96.50、THREE96.31；BASE NEXT95.83、SHIFT95.50；学习分支没有权重/模型级结果；TTFT未完成。它们是项目内精度点估计，不是显著性、效率前沿或外部SOTA。

SHIFT下COVER−BASE：GQA+0.74、POPE+0.07、MMBench−0.08、MME+53.0。按旧包固定分母61.9/85.8/64.1/1852，MME约贡献0.715 R4点，占这组入口差距约71%。这不等于“入口×日程交互的71%”：后者还需减去EARLY的入口差异。两个量必须分别计算。

NEXT相对SHIFT，COVER+0.17、BASE+0.33。新邻域在两入口都有改善，不能全部归于COVER机制。随机设置改善BASE是强控制线索，但不同g/r不是独立seed。

审计报告S0 W=2034，SHIFT已按既有语义重建为2284；若两者的工作量口径一致，增加约12.29%。本环境没有S0原始trace，不能将报告值当作已经复核，也不能反推一个虚构S0日程。恢复原路径ACC、逐层trace和TTFT是必须补的外部锚点。

## 3. 代码级发现及取舍

| 原实现 | 风险 | R2修改 |
|---|---|---|
| 每状态通常标6动作，部署可搜16×16=256动作 | 已采样oracle不能代表部署搜索；预测最大值容易挑中高估误差 | 固定最多16动作的确定性候选目录，默认完整标注同一目录 |
| 单步分支标签，默认线上最多4轮 | 接受后集合上下文变了，后续状态没有直接监督 | 主实验g1r1，最多一次交换；多轮待单步成立后采集真实访问状态 |
| 预测值>0即接受 | 最大值筛选后的正值未必代表真实正收益 | 在图像隔离验证集完整目录上校准阈值，显式允许全局abstain |
| no-context、shuffled仍含历史，current不含 | 消融同时改了历史和上下文/监督 | 两者与current共享历史屏蔽；no-context仅额外去共同集合特征 |
| current/full两权重共同作为就绪条件 | 可选历史消融阻塞主算法 | 只要求current；full缺真实history时明确跳过 |
| 诊断按prefix hash聚合 | 相同前缀可对应不同后续策略和基准集合 | 状态身份含源、图像、问题、入口、日程、层位、horizon、基准集合 |
| 完成一组四任务即标核心已测 | 缺少强控制也容易被误读为闭环 | 分开报告部分ACC、主比较齐全、有效性/效率验证；不自动宣布增益 |
| 部分旧shard存在时不再采集 | 数据不足可能永久阻塞主线 | 可先拟合，再在新文件补采；保留已有数据，按完整状态动作去重 |

候选16、单次交换是本轮识别问题的起点，不是证明最终最优策略。它牺牲了搜索覆盖，换来监督、校准和部署的一致性。如果16候选没空间，不据此否定全部集合交换；先用少量样本扩展到64候选诊断，检查是不是提案瓶颈，再决定是否值得修改在线契约。

## 4. 算法保留什么，为什么不换复杂网络

监督目标仍是同前缀、同层位、同K、同后续策略的总任务收益：

\[
\Delta(h,S,D,I;\pi)=\mathcal L_y(F(h;S,\pi))-\mathcal L_y(F(h;(S\setminus D)\cup I,\pi)).
\]

令共同剩余集合为C=S\D。保留

\[
\widehat\Delta_\theta=v_\theta(I,C,h,\pi)-v_\theta(D,C,h,\pi).
\]

这不是结构错误：真实集合价值本来就能写成两个集合价值之差。应担心的是均值池化的上下文信息损失、训练覆盖和小网络容量，而不是为了表达“集合”就新增一个复杂成对网络。当前50维输入、32隐层、1664参数的差分小头继续作为主候选。

线上顺序：原选择器给出S → 生成最多16个g1交换 → 同一小头批量预测 → 取最大预测动作 → 超过验证阈值且校准策略允许时执行一次，否则维持S → 后续仍走原选择器。

阈值校准使用完整验证目录的选中动作实际收益，按图像平均，包含不交换。候选阈值比较的bootstrap下界只是保守的开发选择规则，**不是搜索后显著性保证**。独立诊断图像和ACC仍要验证。shuffled对照只打乱训练标签，其验证校准流程仍使用真实标签，不能称为完全无监督对照。

本目标是相对集合分配收益，不是“信息已经饱和”，也不单独隔离纯继续交互作用。允许后续重选时，总收益可能来自更好的最终幸存集合。identity-fixed、全层视觉KV处理等干预仅在后端真实支持时报告；不支持就标未测。

## 5. 新近论文怎样改变贡献边界

本轮查阅的原始来源：

- [SCoRe，CVPR2026](https://openaccess.thecvf.com/content/CVPR2026/html/Xu_SCoRe_Salience-Coverage_Reduction_for_Vision_Token_Pruning_in_Vision-Language_Models_CVPR_2026_paper.html)：会议摘要将显著性与覆盖统一到代表性选择。此处只核对原始摘要，没有声称复现全文算法。
- [CoIn，CVPR2026](https://openaccess.thecvf.com/content/CVPR2026/html/Du_CoIn_Coverage_and_Informativeness-Guided_Token_Reduction_for_Efficient_Large_Multimodal_CVPR_2026_paper.html)：原始摘要明确联合informativeness与coverage。
- [SIEVE，2026-08](https://arxiv.org/html/2608.10489v1)：已阅读其跨模态吸收、文本子空间重构残差及方法部分；“视觉信息被文本吸收”不能再作为我们的独有概念。几何可解释性也不等于反事实任务效用，两者需要实测关系。
- [CoRePrune，2026-09](https://arxiv.org/html/2609.26484v1)：集合和深度条件可删性是直接机制近邻。
- [DIPrune，2026-10](https://arxiv.org/html/2610.08341v1)：任务损失出发的跨层演变代理，要求我们与便宜rank变化正面对照。
- [SheafPrune，2026-10](https://arxiv.org/html/2610.13263v1)：冻结骨干、使用语言建模损失训练选择器已存在；核对了其训练与固定配置/逐点包络的区别。不能把“小头+任务监督”单独当创新。
- [Bifocal，2026-10](https://arxiv.org/html/2610.18399v1)：提醒保留OCR和grounding能力，不只优化当前R4。

因此争取的贡献必须落到：**在固定计算路径下，直接反事实任务监督是否提取了廉价代理没有有效利用的条件收益，并形成可部署的精度—真实成本优势。** 它尚未成立，也尚未完成对所有学习式选择方法的新颖性排除。

## 6. 下一轮最小但不僵化的实验

主线12配置：2入口×2日程(SHIFT/NEXT)×3策略(REF/current/同样本同候选目录的匹配交换数随机)。强工作点最多4项：full、no-context、shuffled、E019CUR。full可缺席，不阻塞其他项。共最多16配置、64四任务screen jobs。确认固定保留9配置，另加实际导出的S0/外部锚点；不是只确认screen赢家。

边界随机与RDRIFT的代表性复核、E019 B/C剩余、外部复现、OCR/grounding接口准备作为并行工作。它们不是被宣布失败或取消，也不能再挤掉pairdata与当前头的首轮ACC。GPU6从一开始独占测速，GPU4主采集，0/2先做必要控制、权重就绪后做主ACC。按真实吞吐调度，不承诺半天全量完成所有任务。

从128独立图像/256状态起步、每状态最多16动作，约4096成对动作、约4384次完整重跑（4096动作+256基准+32 no-op；不含可选identity-fixed额外分支）。比旧每状态6动作更贵，应记录每个有效标签耗时和训练数据成本，不以参数小掩盖离线成本。必要时减少图像数先排除接线错误，再补足图像隔离的校准量；不把少量动作当完整目录。

并行完成MME类别/错误迁移、同图2×2交互bootstrap、CSCORE实际选点一致率。`factorial_interaction.py`直接计算四臂交互及图像配对区间；它证明的是交互大小及不确定性，不会自动给出机制。

## 7. 分支收敛规则

| 结果 | 下一步，及停止什么 |
|---|---|
| 无超no-op噪声收益，扩展目录也很弱 | 停止当前位置/提案的评分器扩容；不推广成全部动态剪枝无效 |
| 更大目录才有空间 | 改提案设计，再版本化训练/部署；不直接用更宽oracle给当前策略背书 |
| oracle有空间，held-out选中收益差 | 查上下文压缩、特征与数据量；只做一个预先界定的修复回合 |
| NLL改善，真实生成不改善 | 调整目标或降为代理研究；不以NLL替代ACC |
| 只修复BASE，强COVER无增量 | 研究弱选择器修复的适用范围，不能直接立为广泛优越性 |
| ACC增益被选择器总开销抵消 | 停止当前部署版本，或进一步降低特征/搜索成本 |
| 同成本超过强固定、随机、代理 | 冻结方法，扩展三预算、另一架构、OCR/grounding和近期强基线 |

进入后续阶段的门槛是证据，不是为了保持某个论文故事而要求某模块一定存在。近期工作也允许最终只留下一个简单有效模块；不要求COVER、历史与学习头全部进入论文。

## 8. 论文证据与写作现在如何推进

现在可以写方法目标、预算与位置语义、实验协议、相关工作和已有负结果分析；主表中新方法行保持未测。论文候选主张只保留三项：条件收益现象、低成本可预测性、部署优势，逐项列所需证据。

不能把已反复选型的四任务数据重命名为独立测试。冻结主策略后留出不参与调参的数据/任务，并明确旧结果的开发用途；条件bootstrap不消除赢家偏差。初始R4分母仅属于当前模型，跨架构需该模型自己的dense分数。

本轮改进的是研究与实现的可检验性。代码通过本地检查不提高算法证据等级；只有服务器真实结果才能决定最终投稿方法与论文结论。
