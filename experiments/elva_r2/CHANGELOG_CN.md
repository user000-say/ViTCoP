# 相对本轮要求及可见Stage1源码的修改

这里没有旧仓库或旧ELVA ZIP，因此本文件是设计/接口变更记录，不伪造git diff。

| 部分 | 此前问题 | 本轮实现 |
|---|---|---|
| 最强压缩日程 | 入口短跑后过早缩窄，不覆盖长阶段假设 | 60×10+28×10+12×12=1024；另外两档等比例精确匹配 |
| 层号与预算 | 0-based事件名与完成block数易混用 | 统一完成block后事件；前置trace逐层记录，整数/Fraction核验 |
| Stage1 | 选择几何、评分来源与payload易混淆 | 单层/双层几何与score_guide独立；payload强制原pen；COVER必须绑定原函数 |
| 层采集 | 可能误取第九个数组或重跑ViT | 原生hook同一次前向，完成9→blocks[8]；pen按实际深度解析 |
| RDRIFT | 历史局部索引和当前token身份可能错位 | 提供同活动集合、原ID对齐的明确参考；历史臂仍用原函数，差异先报告 |
| 动态约束 | 贪心推迟可能耗光后续预算 | 枚举严格合法的有限后续路径；没有合法动作不允许借预算 |
| 存活标签 | 旧交换包含最终身份变化，统一故事难验证 | 新临时交换，两组最终都删，固定共同F、窗口与预算 |
| KV机制 | 同最终集合仍可能残留早层视觉KV | 原生/支持对齐两种estimand分开，检查所有已执行层支持 |
| 可选学习 | 旧模型负结果、候选最大值错配 | 拒绝旧schema；同目录单轮；按图像隔离、验证目录校准、允许全不交换 |
| 自动执行 | 权重存在即启动、旧结果被错误复用 | 条件分支检查新证据；结果绑定配置/模型/数据/评分来源和完整trace |
| 交付验证 | 只有集合合法性小测易误当模型验证 | 随机因果decoder真实分支、KV decode、独立生成；明确fixture；PyTorch验证单列 |

`FULL_SOURCE.md`逐文件展开本包全部Python源码；修改/移植应以源码文件本身为准。
